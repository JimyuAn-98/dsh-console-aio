# 提案: 远程部署子工具组(分级授权: 只读增强 → 受控写)

- Status: proposed
- Date: 2026-08-30

## 背景

现状: deployments 页提供清单 CRUD/连接测试/只读快照; DshRemote 有四个只读原语
(read_file/list_dir/dir_stats/exec, 全部走 BatchMode ssh)。红线(AGENTS/README):
**远程只读; 写操作必须显式确认 + 流式日志**。愿景 §二.1: 远程一键安装/更新 dsh、
版本对比、web 健康探测(经隧道)、日志拉取、配置比对——VISION §五.4 的开放问题
(放开受控写还是永久只读)至今未拍板, 是本提案要解决的核心决策。

## 方案(分级授权模型, 分三期)

### L0/L1/L2 授权分级(决策核心)

| 级别 | 内容 | 门禁 |
|------|------|------|
| **L0 只读** | 探测/读取/对比/拉取 | 无确认(现状延续) |
| **L1 受控变更** | 远程安装/更新 dsh、重启远程 web | ① 强确认(列出将执行的完整命令清单) ② 流式日志到页面(页面化不弹窗) ③ 操作前自动记录回滚点(当前 commit hash/备份路径), 失败时给出回滚命令 |
| **L2 破坏类** | 删除/重置/卸载远程数据 | **不提供**(红线不动) |

### R1 只读增强(L0, 无争议, 建议先行)

- **版本对比**: 远程 `git -C <repo> rev-parse HEAD` + 描述 vs 本地, 页面内并排展示
  (复用 DshRemote.exec);
- **web 健康探测**: 经隧道端口 tcp_ok(本机视角), 与 monitor 同源;
- **日志拉取**: 远程日志文件 tail(经 ssh cat/tail, 只读);
- **配置比对**: 远程 settings.yaml vs 本地 diff 视图(只读读取, 双栏高亮)。

### R2 受控写(L1, 需拍板)

- **一键安装/更新远程 dsh**: ssh 单连接执行幂等脚本(不 scp 落盘):
  检查 git/node/pnpm(缺失则报清单终止) → clone-or-pull 仓库 → pnpm install;
- **新增 config 字段** `dash_repo_url`(远程安装源; 现有 dash_repo 是本机路径,
  远程装不了); 前置自检给出远程环境缺失清单;
- **流式回显**: core 新增流式远程序列(ssh exec 逐行读, events 回调契约与
  install_dsh 一致), 超时 + kill 兜底(AGENTS 防御模式);
- 回滚点: 操作前记录远程 commit hash, 失败提示 `git reset --hard <hash>` 命令
  (展示给用户, 不自动执行——保持 L1 人工确认)。

### R3 一键编排(远期)

安装 → 隧道 → 探测 → 诊断报告 串成向导式分步(页面内, 非弹窗)。

## 拒绝的替代方案

- **scp 分发文件再执行**: 多一跳、要管远端临时文件清理; ssh stdin 管道脚本更干净。
- **ansible/fabric 等外部编排工具**: 引入重依赖, 小白用户机器上还要装。
- **免确认静默写**: 违反项目红线。
- **自动执行回滚**: 回滚本身也是写操作, 保持人工确认。

## 影响(若实施)

- core/remote_deploy.py(新) + DshRemote 增流式 exec + deployments 页深化
  (操作组 + 页面内流式日志区) + config 增 dash_repo_url + 单测;
- 红线文档同步(AGENTS/README 安全说明补 L1 分级条款);
- 工作量: R1 约半个工作单元; R2 约一个工作单元(流式 + 回滚点 + 自检)。

## 开放问题(需拍板)

1. **是否接受 L1 受控写**(还是永久只读, R2 永不做)?
2. 若接受: 远程安装源(dash_repo_url)与远程主机环境(git/node/pnpm 可用性)是否具备?
3. R1(只读增强)与 R2 的优先级, 以及与隧道规划器 T1 的先后?
