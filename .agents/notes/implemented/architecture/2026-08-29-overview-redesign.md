# 概览页重设计 + 数据修复（BUG-007/008）

- Status: implemented
- Date: 2026-08-29
- Related: docs/BUGS.md BUG-007/008；用户反馈"概览页内容很空，数据不对/不全"

## 排查结论（三个独立问题）

1. **渲染 bug（BUG-008）**：OverviewPage.refresh 的 worker 把结果经 `app.bridge.emit`
   发出——bridge 是底部日志区的信号桥，`dep_status` 永远停在"读取中…"，快照变成底部
   日志的一行杂音。技术债"概览页直连 core + 裸线程未走 service"的实际代价。
2. **数据 bug（BUG-007）**：`DshRemote.dir_stats` 本地分支只统计子目录**直接文件**，
   而会话目录是 组/会话/文件 三层 → `session_bytes` 恒 0（概览页与部署页快照同源）。
3. **内容空**：整页只有一张卡一行文字；本机现成的用量/任务板/工作区/会话/部署快照/
   隧道探测全部未展示。

## 决策

- **数据通路**：页面级 `_data = Signal(object)` + safe_emit 回 UI；探测走
  `service.ctl.probe`（线程安全，纯 core 对象）；技术债清偿。
- **dir_stats 改有界递归 `_tree_size`**（max_depth=4）：三层会话目录算对，限深防
  符号链接环（.dsh-module-fallback 有 junction）与大目录失控。
- **重设计布局**（沿用 P1 现代卡片语言）：运行状态卡（web 探测圆点+毫秒+本体版本，
  本体版本读 dash_repo/package.json，仅本机）→ 四张速览迷你卡（会话/用量含累计费用/
  任务板/插件与预设）→ 部署列表（ModernList，在线徽章+本体/市场双版本 meta）→
  隧道速览（本机端口本机探、反向隧道 `probe_remote_tunnels` 经 ssh 查公网监听，
  与右栏监控同口径）。
- **口径明示**：快照 version 字段实为 dshmarket 版本，UI 标"市场 vX"；本体版本单独
  标"本体 vY"（仅本机有仓库路径可读）。
- **未配置/演示模式**：远程行显示"未配置"灰徽章而非整页放弃——本机数据照常加载
  （旧实现 ssh_server 未配置时整页只显示占位文字）。

## 放弃了什么

- 部署列表加第三栏详情：概览定位是"一眼总览"，钻取去部署管理页，避免两页重复。
- web_ok 快照字段复用：发现它是死字段（从未置 True），概览自行探测，快照字段留待
  上游清理。

## 验证

- 纯单元 341 例全绿（+2：dir_stats 嵌套三层/缺失目录）。
- 真机离屏冒烟：3080 在线(毫秒)、部署行完整 meta（会话 10 · 70.4MB，修复前恒 0）、
  速览（59 会话/21 归档、6 模型 5025 次 ¥58.46、任务板 0、插件 5/2/3）、隧道圆点。
