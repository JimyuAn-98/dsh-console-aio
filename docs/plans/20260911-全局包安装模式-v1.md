# dsh 全局包安装模式（pnpm -g）

> 日期：2026-09-11 ｜ 状态：**待用户拍板**（方案 A/B 二选一；未落地）
> 关联：`core/env.py`、`core/dshctl.py`、`core/config.py`、`app/services.py`、`ui/pages_dsh.py`、`docs/ARCHITECTURE.md`

## 一、背景（已核实）

1. 官方 npm 包 `@deepseek-ai/dsh` 存在且公开（`apps/cli/package.json`：`bin = { dsh: lib/bin.js }`，`publishConfig.access = public`；npm registry latest = `0.1.5-rc.1`）。
2. **dsh CLI 自身只有 `web` / `plugin` 两个子命令**（`apps/cli/src/args.ts`），没有 `update` / `uninstall` / `self`。
3. 因此「更新/卸载」是 **pnpm 全局包** 的职责（用户实测确认）：
   - 安装：`pnpm add -g @deepseek-ai/dsh[@版本]`
   - 更新：`pnpm update -g @deepseek-ai/dsh`
   - 卸载：`pnpm remove -g @deepseek-ai/dsh`
4. 官方 README 推荐零安装运行：`npx @deepseek-ai/dsh web`；源码方式是 `git clone + pnpm install + pnpm run build + pnpm dsh web`。
5. **本机环境坑**：pnpm 11.7 的全局 bin 目录 `C:\Users\1\AppData\Local\pnpm\bin` 不在 `PATH`，未加入前 `pnpm list -g` 直接报错退出；把该目录前置进 `PATH` 后一切正常（当前 `No global packages found`，即本机用的是源码模式）。
6. 全局包与源码模式共用同一个 `~/.dsh` 数据目录，数据互通，切换不迁移数据。

## 二、现状（源码模式）

| 环节 | 现状实现 |
|---|---|
| 安装 | `core/env.py::install_dsh`：`git clone` → `pnpm install` → `build` |
| 更新 | `core/dshctl.py::update_dsh`：停 web → `git pull` → `pnpm install` → `build` → 重启 |
| 卸载 | `core/env.py::uninstall_dsh`：停 web → `_rmtree_force(dash_repo)` → 清 config |
| 版本 | `dash_repo/package.json` + GitHub Releases；`deploy_dsh_version` 按 tag checkout |
| 启动 | `dash_cmd = ['pnpm.cmd','dsh','web']`，`cwd = dash_repo` |

痛点：安装/更新要 clone + 依赖安装 + 构建（数分钟），卸载要删含只读 `.git` 的整棵目录（BUG-011），对小白用户门槛高。

## 三、方案对比

### 方案 A：双模式并存（推荐）

新增 `config.dsh_install_mode`（`source` | `package`）：

| 环节 | `package` 模式 |
|---|---|
| 安装 | `pnpm add -g @deepseek-ai/dsh[@版本]` |
| 更新 | `pnpm update -g @deepseek-ai/dsh` |
| 卸载 | `pnpm remove -g @deepseek-ai/dsh`（秒级、无残留，彻底绕开 BUG-011） |
| 启动 | 全局 bin 目录前置进子进程 `PATH`，执行 `dsh web` |
| 版本 | `pnpm list -g @deepseek-ai/dsh --json` 解析；切版本 = `pnpm add -g @deepseek-ai/dsh@<版本>` |

优点：对小白默认走官方最短路径；源码模式保留给你（DSH 开发）跑本地未发布代码；两模式数据共用 `~/.dsh`。
代价：两套生命周期都要维护与测试；DSH 管理页需显示/切换模式。

### 方案 B：全面改为全局包模式

删除 `git clone` / `build` / tag 部署流程，安装/更新/卸载/版本全走 `pnpm -g`。代码量净减少、概念最少。
代价：**不能再跑本地未发布的 DSH 源码**（你当前 `D:\Applications\deepseek-harness` 的工作流会断），插件开发/联调也不便。

### 方案 C：不改功能，只补文档

把官方全局包命令写进 README/ROADMAP，本轮先完成源码模式卸载的实机复测。

## 四、方案 A 的分阶段落地（若选定）

- **P1 全局 pnpm 基座**：`core/pkgmgr.py` 新增 `pnpm_global_bin()`（`pnpm bin -g`，失败回退 `%LOCALAPPDATA%\pnpm\bin`）、`pnpm_env()`（把该目录前置进 `PATH`，解决本机报错）、`pkg_installed()` / `pkg_version()`（`pnpm list -g --json`）。
- **P2 包生命周期**：`install_pkg(version)` / `update_pkg()` / `uninstall_pkg()`，全部 `stream_cmd` 流式事件（自动进长操作日志）。
- **P3 启动与版本**：`start_dsh` 在 package 模式下用全局 `dsh web`（`PATH` 前置）；版本卡数据源按模式切换；「部署指定版本」在 package 模式下改为「安装指定版本」（`@版本`）。
- **P4 UI 与配置**：DSH 管理页显示当前模式与安装位置；安装卡在两种模式间切换（写入 `dsh_install_mode`）；卸载卡按模式改文案与确认内容。
- **P5 文档与测试**：ARCHITECTURE 增「安装方式」节、ROADMAP/RELEASE_NOTES、单测（PATH 组装、命令拼装、版本解析）。

## 五、验收

1. package 模式下：安装 → 启动 → 捕获 Token → 更新 → 卸载全链路通，且卸载后 `pnpm list -g` 无残留。
2. 源码模式行为不变（现有 524 单测全绿）。
3. 模式切换不破坏 `~/.dsh` 数据；配置文件热重载生效。

## 六、风险

- **PATH 依赖**：不前置 pnpm 全局 bin 目录时，pnpm 自身报错退出（本机已复现）——P1 必须做，且失败要有中文提示。
- **npm 上最新为 rc**：`latest` 目前是 `0.1.5-rc.1`，控制台「更新」会拉到预发布版；需与 Releases 页的「预发布」标注保持一致。
- **检测已装**：`pnpm list -g` 解析失败（PNPM_HOME 未配）时不能误判为「未安装」。
