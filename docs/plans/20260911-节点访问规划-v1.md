# 节点访问规划：本机/远程 dsh 节点、Token 获取与总览展示

> 日期：2026-09-11 ｜ 状态：**四阶段全部落地**（阶段 1 去重展示 / 阶段 2 配置显式化 / 阶段 3 节点码·runtime·信箱·发现），待用户实机联调验收
> 关联：`docs/ARCHITECTURE.md`（三地拓扑/鉴权信箱）、`ui/pages_overview.py`、`ui/pages_deployments.py`、`core/data.py`、`core/tunnels.py`、`core/tunnel_mgr.py`

## 一、背景与目标

1. 总览页底部的「隧道状态」卡与右侧监控栏重复（且其 `probe/remote_probe` 数据源从未赋值，是张死卡）。
2. 「远程 dsh」没有一等公民地位：`deployments[]` 只有 SSH 连接字段，访问端口/鉴权链接全靠启发式猜；
   总览也看不到"经隧道能否访问远端 web"，且没有"在浏览器打开"。
3. 目标：统一为「节点」概念——本机节点 + 远程节点；配置在部署管理、展示在总览、运行在隧道页；
   Token 获取统一为"远端本机落盘 → 公网信箱镜像"；总览只读并可一键复制/浏览器打开。

## 二、概念模型

```
[实验室/办公室: 控制台 + dsh]
   ├─ 捕获 Token → 落盘 ~/.dsh/.console/runtime.json (唯一事实源)
   ├─ SSH 镜像 ──────────────► 公网 :~/.dsh_runtime/<node_id>.json (令牌信箱)
   └─ 反向隧道 -R ───────────► 公网中转 :8090
                                      ▲
                                      │ 正向隧道 -L
                                [家: 控制台]  access_port
                                → 取 Token(先直连远端 runtime.json, 再公网信箱)
                                → http://127.0.0.1:<access_port>/?token=<token>
```

## 三、数据模型

### 3.1 `config.json.deployments[]`（远程节点）

| 字段 | 含义 | 备注 |
|---|---|---|
| `name` | 显示名（中文随意） | 已有 |
| `host` / `user` / `port` / `dsh_home` | 直连 SSH（LAN 直读 Token / 快照用）；**跨网节点可全部留空**（纯隧道 + 公网信箱访问，快照降级为"未配置"） | 已有；host/user 现为可选 |
| `node_key` | 节点码（= 远端 `node_id`），公网信箱 key | 新增 |
| `web_port` | 远端 dsh web 端口 | 新增（原先靠猜） |
| `access_port` | 本机访问端口（正向隧道 local_port / LAN 直连=web_port） | 新增 |
| `tunnel_id` | 关联正向隧道 id（派生 access_port 与状态） | 新增 |

向后兼容：缺新字段时沿用现有启发式推导，并在详情页提示"建议显式设置"。

### 3.2 节点码 `node_id`（各端 config）

- `MAC → 短哈希`（如 `3f2a91c4d8`），首次运行生成后持久化到 config，可手动改/重置；
- 天然 ASCII（修掉"中文 key 写不进信箱"的 bug）；远端界面显示「本机节点码 + 上次同步时间」。

### 3.3 远端落盘 / 公网信箱文件（JSON）

- 远端本机：`~/.dsh/.console/runtime.json` = `{node_id, hostname, token, updated_at, v}`（唯一事实源）；
- 公网信箱：`~/.dsh_runtime/<node_id>.json` = 同上（镜像，覆盖写入、原子替换）；
- 近端兼容读旧格式裸 `<key>.token`。

## 四、Token 获取顺序（近端）

1. **直连远端**（部署配了 host/user 且 SSH 可达）：`ssh <远端> cat <dsh_home>/.console/runtime.json`；
2. **公网信箱**：`ssh <公网> cat ~/.dsh_runtime/<node_key>.json`；
3. **手动粘贴**兜底。

取不到时给明确中文提示（检查远端控制台是否捕获到 Token、节点码是否一致）。

## 五、信箱治理（避免堆积）

- 节点码持久化 → 每台机器恒为同一文件，每次投递**覆盖**而非新增；
- 文件带 `hostname/updated_at`，近端「信箱管理」列出条目 + 年龄，支持**手动删除**；
- 可选"清理超过 N 天未更新"（**默认关闭**，删除前确认并提示可能影响其他近端控制台）；
- 远端「注销节点」删除自己在公网的镜像（卸载/退役时）。

## 六、页面分工

- **部署管理 = 节点配置**：新增/编辑 `node_key/web_port/tunnel_id`；「从公网信箱发现」`ls` 列出 key+hostname+时间 → 选一个 → 填显示名 + 选正向隧道自动带出 `access_port`；详情页「复制」「在浏览器打开」。
- **总览 = 只读看板**：**删除底部「隧道状态」死卡**；「节点」列表 = 本机节点 + 远程节点（状态 + 鉴权链接 + 复制 + 浏览器打开）。
- **隧道管理 = 运行入口**：启停隧道；反向暴露仍由右栏「公网 :XXX」体现，总览不重复展示。

## 七、状态口径

- 远程节点在线 = 经关联正向隧道探活 `127.0.0.1:<access_port>`；隧道未跑 → 未启动；跑但端口不通 → 异常；
- SSH 快照（版本/会话数）只作详情，不参与在线判定；
- Token 就绪 = 命中直连或信箱；未命中 → 未同步（提示节点码/远端控制台状态）。

## 八、分期实施

- **阶段 1（展示层，低风险）**：删总览隧道状态卡；「部署」区改名「节点」；远程在线改经隧道探活（暂用现有启发式 access_port）；新增「在浏览器打开」。
- **阶段 2（配置显式化）**：`deployments[]` 新字段 + 编辑表单 + 详情链接按钮；读取兼容旧启发式。
- **阶段 3（节点码 + 信箱 + 发现）**：`node_id` 生成/持久化；远端 `runtime.json` 落盘 + 信箱 JSON 镜像；近端「从公网信箱发现」+「信箱管理」；Token 三级获取。

## 九、非目标 / 拒绝的替代方案

- 不做"运行中切换 Mica/纯色"同类的反向暴露展示（右栏已覆盖）；
- 不做全站页面缓存；不改安装输出重复（用户已定保留现状）；
- 远端裸跑 `dsh web`（无本控制台）时不保证自动取 Token（回退手动粘贴）。

## 十、验证计划
